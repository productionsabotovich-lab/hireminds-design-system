# /component <Comp>

Компонент — папка `components/<Comp>/`; экраны собирают продукт только из таких компонентов. Правила ниже
дополняют `CLAUDE.md` и не заменяют его.

## Перед началом

1. Прочитай `docs/brand.md`, `docs/foundations.md` и паттерн компонента в `docs/patterns/`, если он есть
   (каталог — `docs/patterns/README.md`).
2. Проверь каталог `components/index.ts`: нужное может уже существовать как компонент или вариант. Новый вариант
   существующего компонента лучше нового компонента.
3. Паттерн не подходит — не обходи его: опиши в задаче, что именно он не покрывает, и жди решения агента платформы (вопрос в задаче и сообщение сессии `hireminds-platform`).
4. Код компонента расходится с утверждённым макетом или паттерном — это дефект: отдельная задача, а не правка
   на лету в чужой задаче.

## Состав папки

```
components/<Comp>/
  <Comp>.tsx            компонент
  <Comp>.module.css     стили: CSS Modules, только токены
  index.ts              публичный экспорт компонента и его типов
  <Comp>.stories.tsx    Storybook-истории всех вариантов
  README.md             гайдлайн
  preview.html          живое превью для витрины
```

- Имя папки, файлов и компонента совпадает.
- Новый компонент — сразу все шесть файлов и экспорт в `components/index.ts` (компонент и типы пропсов).
- Под-части длинного составного компонента (больше 80 строк) — отдельные файлы в той же папке
  (`PasswordStrengthMeter/PasswordStrengthBar.tsx`); наружу они экспортируются, только если потребитель собирает
  из них содержимое (под-компоненты TerminalBox).

## Код

- **API на пропсах.** Явные пропсы, текст через `children`; компонент описывается JSON-ом — так его собирает агент
  в generated UI. Варианты — перечислением (`variant`, `tone`, `size`), а не набором булевых флагов. Под-компоненты
  на контексте (`Card.Header`) не вводятся.
- **Опциональные пропсы** типизируются как `?: T | undefined` (строгий `exactOptionalPropertyTypes` у потребителя),
  импорт типов React — `import type`.
- **Доступность.** Семантический HTML, видимый фокус (рамка или кольцо `accent`), `aria-*` там, где смысл не виден
  текстом; декоративные элементы — `aria-hidden`.
- Внешний `className` принимается там, где компонент встраивается в раскладку экрана.

## Стили

- Только токены: `var(--ink)`, `var(--space-4)`, `var(--r-md)`, `var(--font-ui)`; стиль текста — по таблице стилей
  в `docs/foundations.md`.
- Точное значение из макета вне шкалы допустимо с комментарием (9px в Brand). Значения 14 и 18px из макетов
  округляются до шага шкалы вверх.
- Запрещено:
  - цвета числами (HEX, `rgb()`, `oklch()`) в CSS компонента, кроме `#fff` для текста на `ink`, `danger` и `accent`
    и исключений, перечисленных в брендбуке (раздел «Что ещё не сделано»);
  - произвольные отступы вроде `padding: 13px 17px`;
  - инлайн-стили `style={{…}}`, кроме динамических значений;
  - импорт чужого `.module.css` и общие CSS-файлы через относительные пути;
  - новые `.css`-файлы вне `<Comp>.module.css`.
- Цвет — по правилу умеренного монохрома (`docs/foundations.md`), контраст — WCAG AA (`docs/workflow.md`, раздел
  «Контраст»).

## README

- Первое предложение — summary компонента.
- Разделы: «Когда использовать», «Пропсы» (таблица: Prop, Тип, По умолчанию, Что делает), «Правила», «Пример».
- По-русски; токены в бэктиках без `--`; примеры — реальные тексты продукта, не lorem ipsum.

## preview.html

- Первая строка — `<!-- @dsCard group="<группа>" height=<N> -->`. Группы: Actions, Brand, Data, Feedback, Forms,
  Icons, Layout, Navigation, Overlays, Terminal, Typography.
- Дальше — HTML-документ, который рендерит `window.Hireminds.<Comp>` через `React.createElement` во всех вариантах
  и состояниях, с реальными текстами продукта.
- Токены, стили компонентов и React подключает render-check и витрина; в превью их не подключай.

## Проверки

```bash
npm run build && npm run typecheck && npm run check
```

- `check` должен показать все превью `ok`; render-check открывает сборку из `dist/`, поэтому идёт после build.
- Скриншоты изменённых компонентов — в `out/shots/`: просмотри каждый.
- Контраст новых и изменённых цветов — до перевода задачи в `In Review`.

## Готово

Задача переходит в `In Review` с PR, превью и скриншотами; после влития PR агентом платформы — `Done`, публикация витрины
(`/publish-library`) и сообщение агенту платформы. Порядок — `docs/workflow.md`.

## Сторонние правила

Скиллы `composition-patterns` и `react-best-practices` — общие правила React. При расхождении с этим скиллом
действуют правила дизайн-системы: компонент описывается пропсами и JSON-ом.
