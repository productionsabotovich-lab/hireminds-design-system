# Работа с заявками

Заявки на доработку дизайн-системы — задачи Linear команды HIR (Hireminds) с меткой `design-system`. Ниже — порядок
работы агента дизайн-системы с заявкой от взятия до закрытия; общий процесс — [конвейер](pipeline.md).

## Источники заявок

- Агент платформы (`hireminds-platform`) — компоненты и варианты для экранов по утверждённым макетам.
- Владелец.

Правки токенов и бренда из Claude Design приходят не заявкой: их находит и переносит скилл `pull-design-edits`.

## Порядок

1. **Просмотр.** В начале работы и по просьбе — задачи HIR с меткой `design-system` в статусах `Backlog` и `Todo`.
2. **Взять.** Статус `In Progress`, комментарий «взял» и короткий план: какие файлы, какие компоненты.
3. **Неясно.** Если непонятно, что делать, или нет критерия «готово», — вопрос комментарием; статус не меняется,
   догадка не реализуется.
4. **Сделать.** Компонент — по скиллу `component`; по утверждённому макету — по скиллу `from-design`.
5. **Проверки.** `npm run build && npm run typecheck && npm run check`: все превью `ok`. Render-check открывает сборку
   из `dist/`, поэтому идёт после build; путь к Chromium — переменная `CHROMIUM`. Скриншоты изменённых компонентов —
   в `out/shots/`. Контраст — по разделу «Контраст».
6. **PR.** Ветка и PR в `main`: что изменилось, скриншоты изменённых компонентов; статус задачи `In Review`, ссылка
   на PR комментарием.
7. **После влития.** Ревью и влитие делает агент платформы. Затем статус `Done` с комментарием: ссылка на коммит
   `https://github.com/productionsabotovich-lab/hireminds-design-system/commit/<sha>`, что изменилось (компоненты,
   пропсы, токены) и что обновить в платформе.
8. **Витрина.** Сразу после влития — скилл `publish-library`.
9. **Сообщение агенту платформы.** Короткое сообщение (SendMessage) агенту `hireminds-platform`: что вышло, коммит,
   что обновить. Источник правды — задача, сообщение — уведомление.

## Особые случаи

- Заявка не про дизайн-систему — комментарий, статус не меняется.
- Дубль — статус `Duplicate` со ссылкой на оригинал.

## Контраст

Каждый новый или изменённый цвет текста, рамки контрола, иконки и индикатора фокуса проверяется до `In Review`.

- Текст — не ниже 4.5:1 на своём фоне; текст от 24px — 3:1.
- Рамки контролов, иконки и индикатор фокуса — 3:1.
- Текст на цветной заливке — `-ink` своей семьи.
- Проверяется каждый фон, на котором цвет стоит: `bg`, `surface`, `bg-2`, `inset`.
- Расчёт — отношение относительной яркости по WCAG 2.x; цвета OKLCH переводятся в sRGB.
- Контраст нового или изменённого токена записывается в его `usage`.
