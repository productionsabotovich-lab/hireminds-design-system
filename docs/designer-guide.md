# Руководство дизайнера

Руководство — правила работы над макетами экранов в Claude Design на дизайн-системе Hireminds. Дизайнер рисует
и код не пишет: макет собирается из компонентов, паттернов и токенов системы, всё новое выносится отдельно
и становится заявкой в дизайн-систему.

## Перед макетом

1. Изучить, что уже есть:
   - каталог компонентов витрины Hireminds — превью и README каждого компонента;
   - [брендбук](brand.md), [основы](foundations.md), [каталог паттернов](patterns/README.md),
     [мудборд «B2 · Frost Graphite»](moodboard/README.md);
   - токены (`tokens.json`): допустимы только эти значения цвета, типографики, отступов, радиусов и теней.
2. Сопоставить каждый элемент будущего экрана с компонентом или паттерном. Экраны, состояния, данные и тексты задаёт
   бриф; правила экранов конкретного продукта приходят вместе с ним.

## Макет

- Макет — холст Claude Design на системе Hireminds: экраны собираются из компонентов витрины.
- Только существующие компоненты, паттерны и токены. Нужного нет — похожий элемент не рисуется: новый компонент
  выносится отдельным артбордом во всех вариантах, размерах и состояниях (покой, hover, фокус, disabled, ошибка,
  загрузка — по смыслу).
- Новый паттерн — повторяющийся составной элемент — сначала описывается на отдельном артборде: назначение, когда
  применять и когда нет, состояния. Только после этого он появляется на экране.
- Новые токены молча не появляются. Если без нового значения нельзя, оно предлагается в карте паттернов
  с обоснованием; решение принимает владелец.
- Цвет — по правилу [умеренного монохрома](foundations.md#умеренный-монохром): главная кнопка `ink`, цвет только для
  состояний. Контраст — WCAG AA.

## Карта паттернов

Макет сдаётся вместе с картой паттернов:

```
Макет: <ссылка на холст>
Экраны и состояния: <список>
Компоненты системы: Topbar, Card, Button (primary, ghost), UserAvatar
Новые компоненты: <имя> (<состояния>) — каждый отдельным артбордом
Новые токены: нет | <имя> — <зачем>
Отступления от брифа: нет | <список>
```

## Если паттерн не подходит

Паттерн не обходится и не подменяется похожим рисунком. В карте паттернов описывается, что именно он не покрывает;
решение принимает владелец, и оно записывается в документацию дизайн-системы.

## Чего дизайнер не делает

- Не пишет код компонентов и экранов: компоненты делает агент дизайн-системы, экраны продукта — агент платформы.
- Не заводит токены и значения вне шкалы молча.
- Не сдаёт макет без карты паттернов.
- Не рисует новый паттерн до его описания.
- Не правит репозитории.

## После утверждения

Каждый новый компонент из утверждённого макета становится заявкой в дизайн-систему: задача HIR с меткой
`design-system`. Агент дизайн-системы реализует компонент, после влития публикует витрину, и следующий макет строится
уже на нём. Порядок — [конвейер](pipeline.md).

## Чек-лист перед сдачей

- [ ] Карта паттернов приложена.
- [ ] Новые компоненты вынесены отдельными артбордами во всех состояниях.
- [ ] Новые паттерны описаны до появления на экране.
- [ ] Новых токенов нет либо каждый предложен с обоснованием.
- [ ] Цвет только по смыслу, главная кнопка `ink`.
- [ ] Контраст текста и контролов — не ниже WCAG AA.
