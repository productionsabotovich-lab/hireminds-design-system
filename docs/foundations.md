# Основы визуального языка

Основы — правила применения цвета, типографики, отступов, радиусов и теней в «B2 · Frost Graphite». Значения хранит
`tokens/tokens.json`; здесь только имена токенов и правила, назначение и контраст каждого токена записаны в его поле
`usage`. Краткая версия — [брендбук](brand.md), настроение — [мудборд](moodboard/README.md), применение
в компонентах — [паттерны](patterns/README.md). При расхождении действует `tokens/tokens.json`.

## Токены

- `tokens/tokens.json` — единственный источник значений. Семейства: `color`, `type`, `spacing`, `radius`, `shadow`;
  токен описывается тройкой `{name, value, usage}`.
- `tokens/tokens.css` генерируется командой `npm run build:tokens` и руками не правится. Цвета, тени, отступы, радиусы
  и семейства шрифтов становятся переменными (`var(--ink)`, `var(--space-4)`, `var(--r-md)`, `var(--font-ui)`),
  каждый стиль текста — классом с именем стиля (`.h1-display`, `.body-base`).
- Стили компонентов используют только переменные. Точное значение из макета вне шкалы допустимо внутри атома
  с комментарием: 9px в Brand, 18px в Card.
- Новый токен или изменённое значение — правка `tokens/tokens.json` с заполненным `usage`. Токены не заводятся молча.

## Цвет

Палитра состоит из графитно-морозных нейтралей и зелёного акцента. Нейтрали заданы HEX и не имеют оттенка,
цветные семьи заданы OKLCH с одинаковой воспринимаемой светлотой; OKLCH не подменяется HEX-приближениями.

### Поверхности

| Токен | Назначение |
|---|---|
| `bg` | фон страницы |
| `surface` | карточки, формы, поля ввода, Topbar |
| `bg-2` | вторичные плашки, hover secondary- и ghost-кнопок, disabled-поле |
| `inset` | утопленные элементы: трек Switcher, код-чип, тело TerminalForecast |

Правило слоёв: глубже — темнее. `surface` не кладётся поверх `bg-2`: белая карточка на сером слое выглядит парящей.

### Текст

| Токен | Назначение |
|---|---|
| `ink` | заголовки и основной текст |
| `ink-2` | подписи полей, текст secondary- и ghost-кнопок |
| `ink-3` | вторичный текст: Lead в hero, текст info-плашки |
| `mute` | приглушённый текст: Lead, Body по умолчанию, Help; читается на любом фоне |
| `dim` | mono-метки и плейсхолдеры; только на `bg` и `surface` |
| `faint` | disabled и декор; не для читаемого текста и не для смысла |

Произвольные серые HEX не используются. Плейсхолдер — `dim`, а не `mute`. На `bg-2` и `inset` вместо `dim` берётся `mute`.

### Линии

- `line` — основной разделитель: граница Card, Topbar, Divider.
- `line-2` — усиленный и пунктирный разделитель.
- `line-3` — рамка контролов (Input, Select): граница поля должна быть видна на 3:1. Разделителями `line-3`
  не служит, рамкой поля не служат `line` и `line-2`.

### Семантические семьи

`accent` (зелёный), `warn` (янтарь) и `danger` (красный) ходят четвёрками: основа, `-2` для hover и нажатия, `-soft`
для заливки, `-ink` для текста на заливке. Текст на цветной заливке — всегда `-ink` своей семьи: на `danger-soft`
пишется `danger-ink`, а не `danger`.

### Умеренный монохром

Интерфейс графитный, цвет обозначает состояние, а не украшает.

- Главная кнопка — `ink` с белым текстом. `accent` кнопки не заливает.
- `accent` — успех и «пройдено»: подтверждение, пройденный этап, живая точка статуса, рамка фокуса, kicker (`accent-ink`).
- `warn` — возврат на доработку и просрочка.
- `danger` — ошибка и лимит; кнопка `danger` — одно разрушительное действие на экран.
- Метки, типы и категории нейтральные (`ink-2`, `mute`, `inset`): цвет не кодирует категорию, ярлыки не раскрашиваются.
- Красный и янтарь появляются только при реальной тревоге. Обычное состояние и нулевой счётчик остаются нейтральными.

### Выбор цвета

| Задача | Решение |
|---|---|
| Главное действие экрана | Button `primary` — фон `ink` |
| Подтверждение успеха | Plate `success` — `accent-soft` и `accent-ink` |
| Предупреждение, возврат, просрочка | Plate `warning`, Pill `warn` — `warn-soft` и `warn-ink` |
| Ошибка, превышение лимита | Plate `error`, Pill `danger` — `danger-soft` и `danger-ink` |
| Разрушительное действие | Button `danger` — одна на экран |
| Технический надзаголовок | Kicker — `font-mono`, `accent-ink` |
| Подпись под полем | Help — `mute` |
| Плейсхолдер | `dim` |

### Запрещено

- Бирюза, фиолетовые градиенты, оттенки зелёного вне семьи `accent`.
- HEX вместо OKLCH для цветных семей: `#16a34a` вместо `var(--accent)`.
- `color: black`. Белый `#fff` — только текст на `ink`, `danger` и `accent`.
- Цветные тени.

### Контраст

Контраст не ниже WCAG AA: текст 4.5:1 на своём фоне; 3:1 для текста от 24px, рамок контролов, иконок
и индикатора фокуса. Контраст текстовых токенов записан в их `usage`, порядок проверки — в [workflow](workflow.md).

Цветной текст на нейтральном фоне (`surface`, `inset`, `bg`) — тоже `-ink` своей семьи: `accent` как текст AA не проходит
ни на одном из них (3.3:1 на `surface`), `danger` — на `inset` (4.27:1). Так набраны счётчики `+n −m` и метки состояния.

Цвета вне токенов (палитра TerminalBox, рамки Plate, фон активного NavLink) перечислены в брендбуке,
раздел «Что ещё не сделано».

## Типографика

Три семейства — три роли. `font-display` (Inter Tight) — заголовки, имя бренда, крупные цифры. `font-ui` (Inter) —
текст, кнопки, поля, подписи. `font-mono` (Geist Mono) — kicker, шаги, ключи, код, лента терминала; абзацы mono
не набираются.

### Стили текста

Стили собраны в `tokens/tokens.json` (`type.groups`); экраны набирают текст атомами, а не размерами.

| Группа | Стиль | Где |
|---|---|---|
| Display | `stage-aside` | StageHeader `aside` |
| | `h1-hero`, `h2-hero` | H1 `hero`; H2 `hero`, StageHeader `hero` |
| | `h1-display` | H1 по умолчанию: auth-формы, центрированные карточки |
| | `form-heading` | FormHeader |
| | `h1-section` | H1 страниц дашборда и настроек |
| | `h2-section`, `h3-card`, `h3-inline` | H2 секции, H3 карточки, H3 строки |
| | `brand-name`, `brand-mark` | Brand |
| UI | `lead-hero`, `lead-page` | Lead |
| | `body-base`, `body-small` | Body и базовый текст страницы |
| | `card-title` | строковый заголовок Card |
| | `button-lg`, `button-md`, `button-sm` | Button |
| | `input-text`, `field-label` | Input и подпись поля |
| | `nav-item` | NavLink, BackLink `subtle` |
| | `help-text`, `caption-ui` | Help, Caption `ui` |
| Mono | `kicker-mono` | Kicker |
| | `caption-mono` | Caption `mono`, StepIndicator, TopbarStatus |
| | `signature` | BrandSignature, ссылки футера |
| | `divider-label` | Divider с подписью, ярлыки групп сайдбара |
| | `terminal-line` | строки TerminalBox |

### Правила

- **Шкала дробная намеренно.** Размеры 10.5, 11.5, 12.5 и 13.5px держат ритм при базовом тексте 13.5px; округлять их нельзя.
- **Веса.** 400 — текст, 500 — кнопки, подписи, kicker, 600 — заголовки, 700 — только буква-марка Brand.
  Уровни различаются размером вместе с весом: пара 400/600 без разницы в кегле читается слабо.
- **Трекинг.** Display — отрицательный, от −0.01em до −0.038em. Текст `font-ui` — без положительного трекинга.
  Mono-метки — положительный, от 0.04em до 0.18em; значения заданы в стилях `tokens/tokens.json`.
- **Mono-метки** (kicker, подписи, счётчики шагов) всегда в верхнем регистре и с разрядкой: без разрядки mono
  читается как код. Код, ключи и строки терминала набираются mono как есть.
- **Акцент в заголовке** — одно слово в `<em>`: H1, H2 и StageHeader выводят его без курсива цветом `accent-ink`.
- **Атомы.** Текст на экранах набирается через H1, H2, H3, Lead, Body, Caption, Help, Kicker; `font-size` в стилях
  экрана не задаётся.
- **Код-чип** — `font-mono` на фоне `inset` с радиусом `r-xs`.
- **Крупные цифры** (метрики, суммы) — `font-display`, вес 600, отрицательный трекинг. Отдельного стиля в токенах нет;
  экран с такими цифрами начинается с заявки на стиль или компонент.

### Антипаттерны

- `font-ui` для заголовков от 28px: теряется сжатый рисунок Inter Tight.
- Mono-метка без верхнего регистра и разрядки.
- Положительный трекинг на основном тексте.
- Вес 400 у заголовков.

## Отступы

Шкала `space-1`…`space-17` с шагом 4px; значения — в `tokens/tokens.json`. Шкала закрыта: новая ступень вводится
только решением владельца.

### Правила

- **Только шкала.** Произвольные числа не используются. Значения из макетов вне шкалы (14, 18px) округляются до
  ближайшего шага вверх; исключение — точные значения внутри атомов с комментарием.
- **Иерархия.** Внутри блока — минимум два разных значения: `gap` между детьми и паддинг контейнера. Между блоками
  отступ больше внутреннего минимум на две ступени.
- **Плотность.** Auth-экраны просторнее (`space-9`, `space-10`, `space-14`), экраны приложения плотнее (`space-3`…`space-5`).
- **Раскладка.** Отступы между блоками задают Stack и Cluster; у детей нет внешних `margin`.
- **Ритм страницы.** Секции — `space-6`, заголовок секции и содержимое — `space-3`, заголовок и подзаголовок — `space-2`.
  Кнопки рядом — `space-2`, группы тулбара — `space-3`, заголовок и тулбар — `space-4`.
- **Форма.** Поля столбцом через `space-4`, перед главной кнопкой — ещё `space-2`.
- **Типовые паддинги.** Страница — `space-8`, низ страницы — `space-15`, внешний паддинг auth-экрана — `space-6`,
  Topbar `app` — `space-4` по горизонтали.

### Антипаттерны

- `margin: 13px 17px` и любые числа вне шкалы в новом коде.
- `gap: 0` между элементами без границы.
- Одинаковый паддинг со всех сторон там, где нужен воздух сверху и плотность снизу (шапка и футер Card).

## Радиусы

Пять значений `r-xs`…`r-xl` и круг `999px` (без токена). Радиус выбирается по уровню элемента, а не по вкусу.

| Токен | Элементы |
|---|---|
| `r-xs` | бейджи, код-чипы, мелкие inline-элементы |
| `r-sm` | вложенные элементы: BackLink `button`, пункт NavLink, квадратный аватар |
| `r-md` | Button, Input, Select, марка Brand, трек Switcher |
| `r-lg` | Card, Plate, Table, EmptyState `block` |
| `r-xl` | модалки (ConfirmDialog) |
| `999px` | точки, круглые аватары, Pill, галочка Kicker |

### Правила

- Чем выше уровень элемента, тем больше радиус: код-чип → поле → карточка → модалка.
- Вложенный элемент скругляется меньше контейнера: вкладка Switcher (4px) внутри трека `r-md`.
- Половинные радиусы вроде `6px 6px 0 0` не используются.
- Аватар — квадрат `r-sm` или круг; радиус 8px превращает аватар в иконку.
- Точные значения внутри атомов (4px у вкладки Switcher, 2px у сегмента PasswordStrengthMeter) остаются в CSS
  компонента с комментарием.

### Антипаттерны

- Радиусы 12–16px: слишком мягко для Frost Graphite.
- Нулевой радиус у карточек и кнопок.
- Большой радиус у маленького элемента: кнопка-«пилюля» с радиусом 999px.

## Тени

Три уровня `sh-1`…`sh-3`; каждая тень — мягкая тень и волосяное кольцо. Тени построены на RGB цвета `ink`
(`rgba(17,20,24,…)`), а не на чёрном; цветных теней нет.

| Токен | Элементы |
|---|---|
| `sh-1` | Card, secondary-кнопка, Table, мелкие поверхности — всегда вместе с рамкой `line` |
| `sh-2` | выпадающие меню, поповеры |
| `sh-3` | только модалки над затемнением |

### Правила

- Сначала граница, потом тень: Frost Graphite «наклеенный», а не парящий.
- Поле ввода тени не имеет. Фокус — рамка `accent` и кольцо 2.5px `accent-soft`; у поля с ошибкой — рамка `danger`
  и кольцо `danger-soft`. Кольцо почти невидимо (1.2:1), фокус держит рамка.
- Plate без тени: вариант задаёт только заливка и рамка.
- Hover меняет цвет, а не высоту: своих теней на hover нет.
- Собственный `box-shadow` рядом с токенами не смешивается; особая тень (кольцо фокуса) живёт в CSS компонента.

### Антипаттерны

- Типовая «карточная» тень `0 4px 12px rgba(0,0,0,.1)`.
- `sh-3` на странице без модального затемнения.
- Цветная тень под кнопкой.
